# Twitch 配信タイムライン & 切り抜き候補モニター

Twitchの配信をリアルタイムで検知し、以下を自動生成するツールです。

- **章立てタイムライン**: 配信タイトル/ゲームカテゴリの変化から章を自動生成
- **切り抜き候補ランキング**: チャットの盛り上がり + 配信音声(声の盛り上がり)を解析し、切り抜きに適した瞬間をスコア順にリスト化

## 従量課金ゼロの設計

| 機能 | 実装方法 | コスト |
|------|---------|--------|
| 配信検知 | Twitch Helix API のポーリング(Client Credentials) | 無料(公式API、レート制限内) |
| チャット取得 | Twitch IRC への**匿名接続**(justinfan) | 無料(トークン不要) |
| 章立て | タイトル/カテゴリ変更のローカル検知 | 無料 |
| 切り抜きスコアリング | ローカルのヒューリスティック解析(正規表現+統計) | 無料(LLM等の外部API不使用) |
| 音声解析 | streamlink + ffmpeg でローカルにデコードしDSP解析 | 無料(全てOSS・ローカル計算) |
| アーカイブ検証 | VODチャットリプレイ(chat-downloader) + VOD音声のローカル再解析 | 無料 |

自宅PCや無料枠のVM(Oracle Cloud Always Free等)で常駐させれば、ランニングコストは一切かかりません。

## セットアップ

1. [Twitch開発者コンソール](https://dev.twitch.tv/console/apps)でアプリを登録(無料)し、Client ID / Client Secret を取得
2. 依存パッケージをインストール:

   ```bash
   pip install -r requirements.txt
   # 音声解析を使う場合はffmpegも必要(streamlinkはpipで入ります)
   sudo apt install ffmpeg        # macOSは brew install ffmpeg
   ```

   ffmpeg / streamlink が無い環境では、音声解析は自動的にオフになりチャット解析のみで動作します。

3. 認証情報を環境変数に設定:

   ```bash
   export TWITCH_CLIENT_ID=xxxx
   export TWITCH_CLIENT_SECRET=xxxx
   ```

4. 設定ファイルを作成:

   ```bash
   cp config.example.yaml config.yaml
   # channels に監視したいチャンネル名(twitch.tv/xxx の xxx)を記入
   ```

## 使い方

```bash
# 設定ファイルで起動
python -m twitch_monitor --config config.yaml

# チャンネルを直接指定して起動
python -m twitch_monitor --channel some_streamer --channel another_one

# 音声解析なし(チャットのみ)で起動
python -m twitch_monitor --config config.yaml --no-audio
```

監視対象が配信を開始すると自動で追跡が始まり、`out/<チャンネル名>/<日付>_<配信ID>/` に以下がリアルタイム更新されます(デフォルト60秒間隔)。

- `timeline.md` — 章立てタイムラインと切り抜き候補ランキング(人間が読む用)
- `highlights.json` — 同内容の構造化データ(他ツール連携用)

配信終了時には最終版が書き出されます。

## 切り抜き候補のスコアリング

チャットを10秒単位で集計し、平常時のコメント速度(指数移動平均)に対するスパイクを検知します。スパイク区間は以下の観点で重み付けされます。

- **コメント速度のピーク倍率**(平常時の何倍か)
- **笑いの量**: 草 / wwww / 笑 / LUL / KEKW など(日英対応)
- **盛り上がりワード**: やば / すごい / 神 / ナイス / Pog / clutch など
- **クリップ要望**: 「クリップ」「切り抜き」「clip」(最も高い重み)
- **エモート密度・ユニークユーザー数**

各候補には「笑い」「盛り上がり」「クリップ希望」「音声の盛り上がり」「チャット急増」のタイプが付き、代表コメントも記録されるので、切り抜き対象の当たりを付けやすくなっています。

## 配信音声ベースの検知(BGM/ゲーム音を考慮)

チャットに加えて、配信音声そのものからも盛り上がりを検知します(`audio_enabled: true`、デフォルト有効)。

1. **取得**: streamlink が配信の音声のみのHLSを解決し、ffmpeg で16kHzモノラルPCMにローカルデコード
2. **BGM/ゲーム音の吸収**: 音量ベースラインを指数移動平均で追従させるため、常時流れているBGMやゲーム音は「平常値」として扱われ、スコアに影響しません
3. **声の判別**: ベースラインから突出した音量のうち、**人声帯域(300〜3400Hz)のエネルギー比率**が高いもの(絶叫・笑い声・悲鳴)を高スコア化。ゲームの爆発音や低音は帯域比率が低くスコアが伸びません
4. **持続音の減衰**: 音量上昇が15秒以上続く場合はBGM切替や戦闘シーンとみなしてスコアを減衰させ、「瞬間的な盛り上がり」だけを残します

音声スコアはチャットと同じ10秒バケットに合流し、複合スコアでランキングされます。チャットが無反応でも音声だけで候補になるため、コメントが流れる前の「叫んだ瞬間」も拾えます。

注意点:

- HLSのライブエッジには数秒〜十数秒の遅延があるため、音声由来のタイムスタンプは数秒ずれることがあります
- 声とBGMの完全な分離ではなくヒューリスティックです。ボーカル入りBGMの急な開始などは誤検知することがあります(持続音減衰である程度抑制されます)

## 配信終了後のアーカイブ検証

配信終了後、アーカイブ(VOD)を元にライブ解析結果の整合性を検証できます。

```bash
python -m twitch_monitor verify out/<チャンネル>/<日付>_<配信ID>
# VOD IDを直接指定する場合(Helix認証不要)
python -m twitch_monitor verify out/... --vod 123456789
# チャットリプレイのみで検証(音声再解析をスキップ)
python -m twitch_monitor verify out/... --no-audio
```

処理の流れ:

1. **VODの自動特定**: Helix APIで配信のストリームIDに対応するアーカイブを検索(`--vod`指定時は不要)
2. **チャット再取得**: VODのチャットリプレイを取得。VODタイムスタンプは正確なので、ライブ時のIRC到着遅延によるずれを補正できる
3. **音声再解析**: VODはファイルなのでffmpegが実時間より高速にデコード。HLSライブエッジ遅延のない正確なオフセットで再解析
4. **照合**: ライブ版とアーカイブ版を突き合わせ、全体のタイムスタンプずれを推定した上で各候補を判定

セッションディレクトリに以下が出力されます。

- `verification.md` — 検証レポート。各候補の判定(**一致** / **ライブのみ=要確認** / **アーカイブのみ=ライブで見逃し**)、ライブ⇔VODのずれ、補正後時間、**そのままシークできるVODリンク**(10秒手前から再生)、補正済み章タイムライン
- `verification.json` — 同内容の構造化データ

ライブ検知の一致率が低い場合はスパイク閾値の調整目安になり、「アーカイブのみ」の候補は見逃した切り抜きポイントの回収に使えます。
